# 受支持的 APK

当前首发只接受**一个**官方安装包版本。这个限制是刻意的：加载器内置了兼容配置（compat profile），把签名器需要的四个成员与固定偏移绑死在那一个构建上，其它版本没有经过验证。

| 项 | 值 |
| --- | --- |
| APK SHA-256 | `001c9a498a41780f6bd42bdaeed2ec3e644ef17afbb6dae0347cafe68c791e3e` |
| 字节数 | 106453626 |
| 必需成员 | `AndroidManifest.xml`、`META-INF/CERT.SF`、`META-INF/CERT.RSA`、`lib/arm64-v8a/libglesv3_1.so` |
| 签名器库 SHA-256 | `d95d7c52daa012a84c644c9e1f62ca31444c989c65773d75400c0cf26bc06d9e` |

本项目不分发这个安装包。使用者需要自己取得官方安装包，并在本地核对它是受支持的那个构建。

## 先自检再提取

```console
xhh-sdk signer inspect-apk <your.apk>
```

命令只读，不会解包或写入任何文件。它逐项对比内置配置并给出结论：

- 退出码 `0` 且 `"supported": true`：可以继续 `signer prepare-apk`。
- 退出码 `1`：`problems` 会写明原因，例如「不是本版本支持的样本」「成员与内置配置不一致」「缺少成员」或「签名器库不是小端 ARM64 ELF」。

每个成员的 `expected_sha256` 与实际 `sha256` 都会列出，因此「差在哪个文件」是可以直接看到的，而不是一句“不支持”。

## 常见情形

- **应用商店里更新过的版本**：`AndroidManifest.xml` 等成员通常不同，`inspect-apk` 会报“不是本版本支持的样本”。首发阶段不支持，需要为该版本新增并验证一份兼容配置。
- **重新打包或修改过的 APK**：即使文件大小接近，哈希也不会匹配，一律拒绝。
- **`libglesv3_1.so` 不同的版本**：加载器依赖该库内部的固定指令偏移，偏移不一致就不能沿用同一份配置。要支持新版本，需要重新核对这些偏移并完成一次真实签名一致性验证。

## 为什么不做“自动适配任意版本”

签名结果必须与平台上真实客户端一致才有意义。配置里的偏移来自对特定构建的静态分析与实测对照；放宽到未验证的构建，只会把失败推迟到请求被平台拒绝的时候，而且看起来像“工具坏了”。首发的选择是：宁可明确拒绝，也不猜测。
