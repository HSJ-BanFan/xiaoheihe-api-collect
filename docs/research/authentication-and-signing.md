# 登录与签名

本报告整理 CLI 的 App 登录和签名路径，并区分源码观察与线上结果。

## 已观察

- App 请求由 Python 客户端构造查询或表单参数，再调用本地签名器生成签名字段。
- 签名器 loader 以 Java 17 或更高版本运行 Unidbg，加载从受支持 APK 提取的 ARM64 原生库。
- Python 包不含 APK、原生库或 JAR。用户需要自行取得受支持 APK，并在本地构建和安装签名器资源。
- CLI 将 APK 提取出的资源与 loader 按摘要保存为本地 signer bundle。账号配置可以引用该 bundle。
- Transport 在首次 App 签名请求时才初始化签名器。离线目录和不使用 App 签名的请求不需要 Java。
- account login --method qr 使用 HTTP 二维码回调。--method browser 使用临时 Playwright 浏览器上下文。
- --method sms 通过 App 签名流程请求短信验证码并提交验证码。账号库使用 Windows DPAPI 保护会话数据。

## 线上结果

2026-10-08 的测试显示，扫码流程能读取 Web SSO 会话字段，但后续 App 和 Web 请求都被平台要求重新登录。短信流程得到的 App 会话通过了账号身份核对，并用于本项目已验收的功能。

风控 cookie 可以由网站页面生成，不要求先完成小黑盒登录。它本身不代表账号会话，也不授予接口权限。

## 分析推断

App 会话、Web SSO 会话和风控 cookie 是不同输入。拿到形态正确的 pkey 不等于服务端接受该会话。App 签名字段只解决请求签名，不替代账号授权或接口权限。

## 未验证

- 只有一个受支持 APK 构建完成了资源校验和签名一致性验收。其他版本不受支持。
- hkey 与 _rnd 的本地一致性不证明任意请求都会被服务端接受。
- 其他用户、账号、设备型号和 Java 版本的兼容性未逐一验证。
- 本项目不提供账号凭据，也不保证用户自行取得的签名器文件安全。

构建和安装步骤见[签名器说明](../../signer/README.md)与[受支持的 APK](../supported-apk.md)。
